# Practical Implementation of HDFS and MapReduce Using Real-World Datasets

## 1. Aim

To implement Hadoop Distributed File System (HDFS) and MapReduce using an e-commerce transaction dataset to calculate the total revenue generated by each customer.

## 2. Problem Statement

E-commerce platforms generate large volumes of transaction data. Analyzing this data helps identify customer spending patterns and understand revenue distribution. This project uses Hadoop HDFS to store transaction data and MapReduce to calculate total revenue for each customer.

## 3. Objectives

- Understand the working of HDFS.
- Store and retrieve datasets using HDFS commands.
- Implement a MapReduce program using Java.
- Calculate customer-wise revenue from transaction records.
- Analyze and interpret the output generated by Hadoop.

## 4. Technologies Used

- **Programming language:** Java
- **Big Data framework:** Apache Hadoop 3.4.2
- **Storage:** Hadoop Distributed File System (HDFS)
- **Processing model:** MapReduce
- **Build tool:** Apache Maven
- **Development environment:** GitHub Codespaces and Visual Studio Code
- **Dataset format:** CSV

## 5. Dataset Description

The input file is `data/transactions.csv`.

| Column | Description |
|---|---|
| customer_id | Unique customer identifier |
| product | Name of the purchased product |
| quantity | Number of units purchased |
| price | Price per unit |

The dataset contains 10 transaction records and one header row.

## 6. System Design

The system consists of the following stages:

1. **Data input:** E-commerce transaction records are stored in a CSV file.
2. **HDFS storage:** The dataset is uploaded to `/ecommerce/input/transactions.csv`.
3. **Map phase:** The Mapper reads each transaction, calculates quantity multiplied by price, and emits the customer ID with the transaction revenue.
4. **Shuffle and sort:** Hadoop groups the intermediate revenue values by customer ID.
5. **Reduce phase:** The Reducer adds the revenue values belonging to each customer.
6. **Output:** The final customer-wise revenue totals are stored in HDFS and copied to the local output folder.

## 7. Methodology

### Step 1: Prepare the dataset

Create the CSV file containing customer IDs, products, quantities, and prices.

### Step 2: Configure HDFS

Configure the Hadoop filesystem and local NameNode and DataNode storage directories.

### Step 3: Start HDFS services

Start the NameNode and DataNode daemons.

### Step 4: Upload the dataset

Create the HDFS input directory and upload the transaction file.

### Step 5: Develop the MapReduce program

Implement a Java Mapper to calculate transaction revenue and a Reducer to aggregate revenue by customer.

### Step 6: Build the application

Use Maven to compile the Java source code and package it into a JAR file.

### Step 7: Execute the MapReduce job

Run the Java application with the Hadoop classpath, using the HDFS input and output paths.

### Step 8: Retrieve the output

Read the generated result from HDFS and save a local copy as `output/revenue_results.txt`.

## 8. MapReduce Logic

The revenue for each transaction is calculated as:

**Transaction Revenue = Quantity × Price**

The total revenue for each customer is calculated as:

**Customer Revenue = Sum of all transaction revenues for that customer**

The Mapper emits the customer ID as the key and transaction revenue as the value. The Reducer sums all revenue values for each customer.

## 9. Results

The MapReduce program processed the transaction dataset successfully.

## 10. Result Analysis

- Customer C101 generated a total revenue of 65,000.
- Customer C102 generated a total revenue of 63,000.
- Customer C103 generated the highest revenue of 77,000.
- The overall revenue across the 10 transactions was 205,000.
- The MapReduce job successfully grouped transactions by customer and calculated the corresponding revenue totals.

The results demonstrate how Hadoop MapReduce can process transaction records and aggregate data using a key-value approach.

## 11. Conclusion

This project demonstrates the practical implementation of HDFS and MapReduce using an e-commerce transaction dataset. HDFS was used to store the input data, while a Java MapReduce program calculated total revenue for each customer. The successful execution and verified output illustrate the use of Hadoop for distributed data storage and batch processing.
